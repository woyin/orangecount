# G04 查询错误定位与输入组合首轮记录

日期：2026-10-08。G04 的代码路径和 headless 集成已补齐；真实 macOS 输入法/原生窗口验收仍归 G37。

## 已验证

- 核心查询解析器返回包含 emoji 前缀的 `unknown-column` UTF-8 字节区间；Go UI 查询页通过真实 `QueryResponse` 定位范围，确认用户接着输入时替换的是错误 token。
- 新增 `Model.locateQueryError`，统一检查错误范围、当前草稿和执行文本身份，再调用 MyGo 公开 rune 选区 API。UTF-8 转换或编辑器选区失败时不替换草稿，并保留输入法提示。
- 应用级测试在标记组合期间调用错误定位路径，确认查询草稿不被更改且返回“组合尚未结束，错误定位已保留”。MyGo API 自身测试覆盖组合文本、undo、caret reveal 和滚动。
- 新增真实原生窗口测试 `TestNativeQueryErrorSelectsUnicodeRangeInInputClient`：执行包含 emoji 前缀的查询，检查真实核心响应的 UTF-8 `missing` token range；点击“定位到查询错误”后，从 AppKit Native Input Client 读回相同文档及正确 UTF-16 选区，再提交 `account` 并确认只替换错误 token。该原生场景连续10次通过。
- `apps/goui/third_party/mygo` 固定在 `869768d02d9154d5b2f9f3a6ebb39767f8f96983`；公开补丁与许可证/来源记录见 `apps/goui/patches/mygo-selection-api.md` 和 `apps/goui/third_party/mygo/UPSTREAM.md`。

## 验证命令

```sh
cd apps/goui
GOWORK=off CGO_ENABLED=0 go test ./internal/widgets/queryeditor -count=1
GOWORK=off CGO_ENABLED=0 go test ./internal/app -run 'TestQuery(ErrorNavigationDoesNotMoveMarkedInputComposition|PageLocatesUnicodeParserRangeInEditor)' -count=1
```

以上命令均通过；`make goui-native-e2e` 的14项原生窗口场景也通过。Native Input Client 检查证明系统文本客户端拿到正确 UTF-16 选区，并能在该位置接收提交文本；它仍不等同于视觉检查屏幕选区/caret、真人输入法候选翻页和取消，因此 G04 保持进行中。

## 2026-10-08 真实输入法候选窗尝试

在隔离 Go UI development 窗口中打开公开 `cashflow.bean`，进入 BQL 查询编辑器后尝试逐键输入 `nihao`。系统当前启用 ABC 和 Squirrel 简体输入源，设置的切换键是 F18 / Control-Option-Space；通过 CUA 发送两种快捷键后，字符仍以 ASCII 原样进入编辑器，已选输入源仍是 ABC，没有出现 Pinyin marked-text 或候选窗。尝试通过 System Settings 暂时关闭文档自动切换时，系统窗口捕获返回 ScreenCaptureKit `-3811`，因此未更改任何系统输入设置。CUA 按键注入无法建立真人输入法场景，不记作通过。随后清空测试查询草稿、将界面语言恢复为简体中文并退出临时 app，没有保存查询/预设；ABC 输入源保持原状态。候选翻页、回车/取消、窗口切换及屏幕选区/caret 仍需真实输入源和目视验收。
