# G14 语义配置预览与应用初版证据

日期：2026-10-07。此记录证明 G14 首轮 Go UI 与工作区实现及自动化检查，不代表 G14、P2 或 macOS 客户端迁移完成。

## 实现

- 增加“语义配置”页面，基于核心 `migration` view 对同一输入生成 Legacy/V3 摘要和差异计数；默认不请求或展示逐条详情、账户名和精确金额。
- 预览读取使用当前 profile 的 `SnapshotID` 约束响应。迁移 `InputIdentity` 标识输入图字节，profile 快照 ID 还包含语义 profile，因此二者分别用于读取一致性和应用前的输入一致性校验。
- 用户明确选择“应用 Legacy/V3”后，工作区创建新 epoch 并打开新 Session。核心在构建过程中再次校验 `InputIdentity`；输入有变化时拒绝打开，旧 Session 和最后有效状态保留。
- 成功应用后新 Session 的响应为空，旧查询草稿清除，选定 profile 写入该账本的偏好。账本文件只读，不由语义切换路径写入。
- 失败提示保留当前工作区。profile 切换复用现有 workspace open 生命周期，因此会使在途 query 与 report capture 失效。

## 验证

- `TestSemanticsPreviewIsSnapshotBoundAndApplyPersistsOnlyAfterOpen`：headless 页面、当前快照约束、counts-only 请求、成功后偏好持久化及查询草稿清理。
- `TestSemanticsApplyRejectsPreviewFromDifferentWorkspaceSnapshot`：拒绝与当前 profile 快照不匹配的预览响应。
- `TestProfileReplacementAcceptsMatchingPreviewAndRejectsStalePreview`：相符输入可切换到 V3；输入改变后应用被拒绝且保留原 V3 Session。
- `TestProfileReplacementCancelsAndClearsReportCapture`：profile 替换时取消在途捕获，且新 Session 不继承旧 capture 状态。既有 `TestOpenAndCloseCancelActiveQuery` 覆盖工作区替换使在途查询失效。
- `TestMigrationPreviewCannotSwitchChangedInput`：核心迁移预览绑定输入图并拒绝过期输入。
- 当前源码验证通过：`make goui-check`；Go UI 相关 `go test -race`；Go UI `CGO_ENABLED=0 go vet ./...`；根模块 `GOWORK=off go test -count=1 ./...`；`make license` 和 `git diff --check`。

## 2026-10-08 初次 Legacy 无效时的 profile 恢复补充

真实包验收发现初始 Legacy 评估无效时，Migration response 虽包含有效 V3 对照，但空 SnapshotID 被误判为过期，界面持续显示加载文案。现以无效 ledger 的 revision 与 entry path 绑定预览，且旧 revision 仍被拒绝；真实 MyGo 窗口连续3次通过初始错误→应用 V3→同源有效 Session。race、`make goui-check` 与完整 native gate 均通过。细节见[G14 无效 Legacy 恢复证据](goui-p2-g14-invalid-legacy-recovery-2026-10-08.md)及[G43 最新包可见验收](goui-p7-g43-semantics-recovery-visible-2026-10-08.md)。这补足了上述“迁移案例 UI”缺口；query/capture 并发宽矩阵及真人 VoiceOver仍未验收。
