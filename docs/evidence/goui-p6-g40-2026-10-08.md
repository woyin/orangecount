# G40 workspace 生命周期 soak 首轮记录

日期：2026-10-08（Asia/Singapore）。本记录验证 Go workspace 与真实 `desktop.Session` 的生命周期边界，不代表原生窗口和系统面板的完整 soak。

## 验证边界

- 测试 seam 使用 `workspace.Controller.Dispatch/State/Done` 与生产 `DesktopEngine`，数据来自仓库公开 `testdata/fixtures/native/cashflow.bean`。
- 不读取私人账本，不调用测试私有方法，不替换真实 desktop session。

## 场景与结果

- `TestTwentyDesktopWorkspaceOpenCloseCyclesReleaseWork`：20 次创建独立 Controller、打开真实 fixture、在 2ms watcher 间隔下等待 Ready、关闭并等待 `Done()`。每轮均结束于 `PhaseClosed`，且不残留报告响应、查询响应或捕获。
- `TestSixtyDesktopReloadsFinishBeforeWorkspaceClose`：对一个真实 Session 连续手动 Reload 60 次，每次都等到异步操作结束，并确认 ledger 仍有效、路径与 SnapshotID 未变；完成后关闭并等待 `Done()`。
- 定向测试普通运行通过：20 次循环 0.02s，60 次重载 0.08s，workspace package 总计 0.642s（`-count=1`）。
- 同两项在 race detector 下通过：`GOWORK=off CGO_ENABLED=0 go test -race ./internal/workspace -run 'TestTwentyDesktop|TestSixtyDesktop' -count=1`，workspace package 1.453s。

## 2026-10-08 原生窗口循环补充

- 新增 `TestNativeTwentyWindowOpenCloseCyclesReleaseWorkspaces`：在一个已运行的 Go UI E2E 进程中，连续20轮创建独立 MyGo Content 窗口、打开公开 `cashflow.bean`、等待财务概览在原生 Accessibility 树中出现、销毁窗口并关闭 model。每轮等待 `workspace.Done()`，确认最终 `PhaseClosed`，且不保留报表 response、query response 或 capture；每轮 GC 后读取当前测试进程的 RSS（`ps`）和 Go `HeapAlloc`。
- 新增 `TestNativeQuerySavePanelClosesWithOwnerWindow`：真实窗口执行查询并冻结成功结果，打开原生 query `NSSavePanel` 后关闭 owner window；确认 sheet 消失、另一窗口没有孤立 sheet、workspace 进入 `PhaseClosed` 并释放 query response/capture，且没有写出文件。定向原生场景连续5次通过。
- 新增 `TestNativeQueryCaptureOwnerCloseDiscardsLateCapture`：真实窗口执行查询后点击“保存 CSV”，通过 gate 将真实 Session 的 query-capture 调用挂起在 Save Panel 打开之前；关闭 owner 后确认关闭等待该操作，面板没有打开，随后释放 gate 并确认 workspace 到达 `PhaseClosed`、不发布捕获结果、无孤立 sheet/文件。定向原生场景连续5次通过。
- 新增 `TestNativeQueryExecutionOwnerCloseWaitsForLateSessionCall`：真实窗口通过原生查询按钮发起查询，并把底层 Desktop Session 的 `ExecuteQuery` 调用挂起；关闭 owner 后确认 workspace 尚未提前结束，释放 session call 后再验证它丢弃迟到结果、没有打开 Save Panel 或写出文件。该场景连续5次通过。
- 定向原生测试 `./apps/goui/native-e2e.sh -run '^TestNativeTwentyWindowOpenCloseCyclesReleaseWorkspaces$' -count=3 -v` 通过，总计60轮真实窗口/账本打开关闭。Go UI全套 `make goui-native-e2e`（24项）、普通 `make goui-check`、全量race、vet和无opt-in原生测试跳过检查均通过。
- 经校正的第一次20轮中，RSS 从114,944 KiB升到约124,416 KiB，随后cycles 11–20最大只增加约0.5 MiB；同进程后续两组20轮的首末变化分别为+336 KiB和+48 KiB。GC后的HeapAlloc在启动缓存升温后约1.4–1.85 MiB，后半段增长阈值检查通过。这个短样本显示初始化期间有缓存升温，后续窗口循环没有观察到持续线性增长；它不是长时RSS平台期证明。
- 诊断过程中发现首版测量循环每轮调用 `t.Cleanup` 注册闭包，闭包捕获已关闭的model/window并将它们保留至整个测试结束，造成RSS/heap假增长。测试改为每轮作用域内defer清理、等待关闭并在GC前清空引用后，增长走势稳定；不将测试 harness 造成的假象归因于MyGo产品代码。

## 2026-10-08 查询执行关窗补充

`TestNativeQueryExecutionOwnerCloseWaitsForLateSessionCall` 使用真实 MyGo 窗口与 `DesktopEngine`，将 session 的 `ExecuteQuery` 调用挂起在测试 gate，随后关闭 owner。断言 `workspace.Done()` 不会早于调用释放；释放后 workspace 进入 `PhaseClosed`、不保留 report/query/capture response，不打开原生保存面板，不生成导出文件。定向 `-count=5` 与其后的完整 `make goui-native-e2e` 均通过。当前原生测试入口总计32个：31项常规窗口场景和1项独立十分钟 soak。

`TestNativeQueryRunningAndSavePanelOwnersCloseConcurrently` 同时运行两个真实窗口：一个窗口的 `ExecuteQuery` 被 gate 挂起，另一个窗口持有冻结 query capture 并显示真实 `NSSavePanel`。测试连续关闭两个 owner，确认面板立即消失、查询 workspace 等待底层调用，随后两边均释放 response/capture、无迟到面板且没有导出文件。定向 `-count=5` 通过。并入完整 `make goui-native-e2e` 后，当时共有33个 `TestNative...` 入口：32项常规窗口场景和1项独立十分钟 soak。

## 2026-10-08 MyGo 已关闭窗口监听器清理补充

MyGo 的 `windowHandler.Closed()` 在 `OnClosed` 回调执行后清除 Window 与 Page 的全部事件监听器。此前窗口的 native surface/timer 会销毁，但这些 listener slice 仍保留；应用 `OnClosed` 闭包可能因此继续引用已关闭的 model/workspace。新增 `TestClosedWindowReleasesEventListeners`，注册各类 Window/Page 生命周期、输入、拖放、下载及导航监听器，关闭窗口后验证 `OnClosed` 恰好触发一次且所有 listener slice 长度归零。该单测 `-count=5` 通过。

修改后的 MyGo 可运行包测试集（`go list ./...` 中排除依赖缺失仓库资源的 `internal/e2e` 和 `cmd/mygo`）共22包，通过 `GOWORK=off CGO_ENABLED=1 go test <packages>`。MyGo 仓库完整 `go test ./...` 仍受此 vendored checkout 的上游内容缺失限制：`internal/e2e` 引用了不存在的 `plugins/fetch`，`cmd/mygo` 测试需要不存在的 `packages/cli/index.d.ts` 与 `node_modules/mygo-cli`，这些不属于本次改动。

修改后 `make goui-check` 与全套 `make goui-native-e2e` 均通过。监听器清理修补减少已关闭窗口对事件闭包的保留；随后补充的原生计数验证见下一节。持续空闲期间的账本文件内容读取仍未测量，G40继续进行中。

## 2026-10-08 stat-only idle watcher 回归

将 `Store.Watch` 的循环抽为私有方法，并将初始 source graph loader 作为内部依赖传入；公开 API 仍固定使用 `source.LoadGraph`。新增 `TestWatchLoadsSourceGraphOnceWhileIdle`，以计数 loader 启动真实 watcher，在账本保持不变时连续等待10个5ms轮询间隔，然后关闭 watcher；测试确认完整 graph load 只发生一次。该测试 `-count=20` 通过。它覆盖 watcher 不重复调用解析图加载路径，不等价于操作系统层面对进程全部文件读取的追踪。

本轮验证通过：

```sh
go test ./internal/snapshot -run '^TestWatchLoadsSourceGraphOnceWhileIdle$' -count=20
go test ./...
go test -race ./internal/snapshot
go vet ./...
make goui-check
make goui-native-e2e
```

`fs_usage` 级别的实际进程 idle 文件读取归因仍未完成；G40 保持进行中。
