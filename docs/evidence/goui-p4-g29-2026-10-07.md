# G29 离线分析文件阅读验证记录

日期：2026-10-07 至 2026-10-08。本记录保存离线 `.ocanalysis` 阅读的实现与验证证据；G29 已验证，不表示 P4 或 Go UI 迁移完成。

## 实现

- 查询页提供 MyGo 原生 Open 面板，仅筛选 `.ocanalysis`。选择文件后在后台读取；普通文件和查询字节预算先行校验，再交给 `desktop.ReadQueryAnalysis` 验证 ZIP 成员、JSON、typed cells、CSV 一致性、fingerprint、支持的 format/contract 与完整性。
- 离线 capture 作为独立只读结果覆盖当前查询结果区域，显示文件名、producer、format、typed contract、原查询、snapshot/profile/evaluation、capture scope、行数和截断状态。archive 中不含原账本路径时，UI 不推断或展示来源账本文件名。
- 打开文件不调用 `workspace.Controller`，也不会把捕获中的查询自动写入草稿或重新执行。用户可以显式填入草稿并单独执行，或者关闭离线捕获回到未改变的活动查询。
- 离线结果沿用 G27 的类型化详情、稳定选择和行复制；捕获未保存工作步计数时，UI 明确说明该字段不可用。

## 验证

- Go UI `TestOfflineQueryAnalysisLoadsTypedResultWithoutTouchingActiveLedger` 从真实 Session 写出 `.ocanalysis`，再用文件 reader 读取并呈现复合 position 全成本；确认活动账本路径和活动查询上下文未变。
- 同测试确认“填入捕获查询草稿”不执行查询、“关闭离线捕获”返回活动查询结果，并拒绝损坏及超过查询字节预算的文件。
- 根模块 `internal/desktop/query_analysis_test.go` 新增旧 `typed-v1`、`typed-v2` 与当前 `typed-v3` scalar archive 兼容测试，并检查未知 contract 和未来 format 被拒绝；原 reader 还覆盖零行 schema、typed cells、CSV mismatch、资源上限和损坏 archive。
- 当前源码检查通过：`make goui-check`；`GOWORK=off go test -race -count=1 ./...`（`apps/goui`）；`GOWORK=off CGO_ENABLED=0 go vet ./...`（`apps/goui`）；`GOWORK=off go test -count=1 ./...`（根模块）；`make license`；`git diff --check`。
- 当前 Mac 的 `OrangeCount Go UI QA` 实机窗口用原生 Open 面板打开合成 `query-result.ocanalysis`。界面实际显示 `format 1`、`beanquery-0.2.0-typed-v3`、捕获范围和一条完整 typed position；成本金额、日期和标签均可见。
- 实机点击“填入捕获查询草稿”后，辅助功能树同时显示捕获查询已写入 BQL 输入框及“尚未执行”；点击“关闭离线捕获”后，捕获视图消失，查询工作台保留该草稿。该验收只使用由公开 fixture 生成的合成文件，没有读取私人账本。
