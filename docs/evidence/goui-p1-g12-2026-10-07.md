# G12 按账本持久化列布局首轮记录

日期：2026-10-07。本记录证明版本化偏好文件已保存并恢复 Go UI 表格列布局，不表示 G12 或 P1 完成。

## 实现

- `preferences-v1.json` 为账本偏好增加列宽字段；现有列顺序字段继续按稳定表格 ID 保存，列宽按表格 ID 和稳定列 ID 保存。
- 流水、账户详情、商品/价格、持仓表、报表账户树及分录/精确值表格会在打开账本时恢复布局。切换账本会先清空窗口内旧账本的布局，再恢复新账本配置。
- 查询结果列布局按类型化结果 schema 的 SHA-256 摘要隔离；相同 schema 可恢复顺序和列宽，不同 schema 使用自己的布局。普通查询草稿、查询文本、结果行和列标题均未写入偏好。
- 列布局变更在 UI 帧后采样，通过每窗口单一后台写入循环合并连续变更；Store 的串行 read-modify-write 保留同一账本的筛选、语义和附件偏好。账本键仍是规范路径的单向 identity。
- 偏好校验限制每账本最多32张表、每表最多128列，列宽限制为16至10000 DIP；布局数组和嵌套宽度map在读写边界进行深拷贝。

## 验证

- `GOWORK=off go test -race -count=1 ./internal/preferences ./internal/app`（`apps/goui`）通过。
- `TestColumnLayoutsPersistAndRestorePerLedger` 覆盖异步保存、重新读取、列顺序与列宽、偏好字段保留，以及两个账本间不串布局。
- `TestQueryColumnLayoutIsolatedByResultSchema` 检查不同 typed schema 取得不同的布局键并恢复各自的布局。
- `TestColumnWidthsRejectInvalidSchema` 覆盖宽度上下限和非有限数拒绝。
- `make goui-check` 和 `GOWORK=off CGO_ENABLED=0 go vet ./...` 通过；`git diff --check` 通过。
