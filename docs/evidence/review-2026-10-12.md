# fix 修订与当前分支合并审查

日期：2026-10-12。结论：**外部修订有已验证的价值，但不能直接合并当前 `main`，也不能用其 Native Preview 3 替代当前 `apps/goui`。**

当前基线为 `1c2096d435e07cc9b5a5957e0e974546ee1387a6` 加本轮开始时的未提交工作树。没有把只含 HEAD 的版本当作当前实现。本轮没有修改当前业务源码，没有提交或合并。CSV 补丁只应用到临时解压副本。

## 1. 修订是否解决当前问题

| 范围 | 本轮观察 | 对当前版本的判断 |
| --- | --- | --- |
| 标准 BQL 缺口 | 同一合成账本下，当前 typed 查询拒绝 `DISTINCT`、`HAVING`、子查询、`PIVOT BY`；外部 v16 均正确返回本用例的预期结果。普通查询和大整数控制例双方通过。 | 外部实现覆盖了当前已知缺口。但当前工作树未接入这些实现，当前问题仍存在。不能把这六个用例扩大成完整查询等价。 |
| 插件结果缓存 | 固定账本内容、文件身份、大小和 mtime，仅改变 Go 回调。旧核心第二次仍返回 `2.3400`，v16 返回新金额 `5.6700`，回调执行次数由 1 增至 2。缓存 race 回归通过。 | 确实修复外部核心的陈旧结果。当前 OrangeCount 阻断用户 `plugin` 声明，没有对应注册/执行和 completed-ledger 缓存接口。不能计为当前产品问题已修复。 |
| CSV 周日期 | 补丁前 `%G/%V/%U/%W` 不支持；补丁后 `2020-W01-1` → `2019-12-30`，`2020-W53-7` → `2021-01-03`。无效周、字段冲突、缺失字段明确报错，失败不返回部分 entries。 | 修复外部 CSVImporter 缺口。当前工程没有 `fava.CSVImporter` 或相应 `DateFormat` 路径。需要另做功能映射与移植。 |
| `currency_accounts` / `sellgains` | Preview 3 的金融插件回归包含在本轮通过的 Native 单元测试中。旧预览失败对照和原版 oracle 来自交付包，未重新生成。 | 修复针对外部内置插件路线。当前无插件产品不执行这两个插件。 |
| Native Fava Go | 原生账户、交易、查询、来源、诊断界面已有实现；规范 TMPDIR 下本机单元测试通过。 | 仍不足以替代当前 Go UI。具体缺口见 Spec 轴。 |

CSV 周日期采用更严格的输入契约。交付夹具中有 10,610 个明确拒绝原版接受输入的案例。这些拒绝是被测试的行为差异，不是 Python 等效通过项。当前 OrangeCount 尚未批准或接入这套导入契约。

## Standards

这一轴检查当前工程的来源、接口及行为约束。以下 `C/` 指解压后的 `beancount-go-fava-go/`；`N/` 指解压后的 `Fava-Native-macOS-ARM64-Preview-3/Source/`。原始包保留在 `fix/Beancount-Go-Fava/`。

1. **P1，硬性来源声明冲突。** `C/THIRD_PARTY_NOTICES.md:10` 声明上游翻译移植；`C/engine/booking.go:1`、`:2` 保留上游版权和 `GPL-2.0-only`。`N/README.md:31` 也声明整体 GPL。当前 [NOTICE](../NOTICE) 声明独立 clean-room、不包含或链接 Beancount 源码。直接纳入会使当前来源声明失实。这是工程声明与架构冲突，不是法律结论。

2. **P1，硬性接口冲突。** `N/go.mod:6`、`:19` 绑定 `beancountgo`；`N/internal/ledgerapp/document.go:14`、`:82` 调用其独立 loader/query/engine。CSV `source.patch:77` 同样依赖 `beancountgo/fava`。当前 [ADR-0051](../docs/adr/0051-use-mygo-native-go-ui-for-the-desktop-client.md) 要求复用当前核心与 `desktop.Session`。修改 module 名不能完成接口迁移。

3. **P1，硬性行为冲突。** `N/app.go:244` 保存源账本，`:378` 创建报表 WebView；`N/internal/ledgerapp/fava.go:33` 启动 HTTP 服务。当前 ADR-0051 与 [设计 R01](../docs/mygo-native-desktop-design-2026-10-07.md) 要求业务窗口无 WebView，并保留本次原生迁移的源账本只读范围。

4. **P2，依赖迁移判断。** `N/vendor/github.com/egoist/mygo/ui/api_gen.go:4017` 的 `SetTextSelection` 返回 `ui.Element`。当前 `apps/goui/internal/widgets/queryeditor/offset.go:38` 要求返回 `bool`，当前 fork `ui/editor.go:729` 提供该接口。直接替换 MyGO 依赖会破坏现有调用，需要独立适配和验证。

Standards：4 项；最严重的问题是来源声明冲突。未把代码气味启发式当作硬性规范错误。

## Spec

这一轴检查当前已接受的产品要求。以下是静态代码路径判断；没有把单元测试通过解释为现场 GUI 验收。

1. **P1：插件行为改变产品契约。** 当前 [完整兼容计划](../docs/beancount-complete-compatibility-plan-2026-10-02.md):7 要求“产品不加载Python模块，不引入插件注册/发现/执行机制”。当前 `internal/ledger/parser.go:503` 报 `E-PLUGIN-UNSUPPORTED`，快照拒绝错误输入。外部 `N/vendor/beancountgo/loader/helpers.go:187` 执行账本插件。整套替换会改变含 `plugin` 账本的接受条件。

2. **P1：原生报表和阅读功能缺失。** R01 要求“业务窗口全部 Go ui；无 WebView/JS/前端服务器”；R06 要求“现有全部 macOS 阅读页面及全指令/配置功能完成”。外部 `N/view.go:13`、`:75` 只有账户、交易、查询、来源、诊断页。报表使用 `N/app.go:378` 的 WebView 和 `N/internal/ledgerapp/fava.go:33` 的 loopback 服务。持仓、价格、趋势、全指令、分析文件读取及附件原生页面缺失。

3. **P1：错误重载可替换有效分析。** R04 要求“错误重载保留有效分析且清楚标为旧数据”。`N/internal/ledgerapp/document.go:109`、`:141` 将 `l.Errors` 转为诊断后仍返回成功；`N/app.go:172` 随后调用 `setDocument`，`:95` 关闭旧账本，`:98` 替换。该代码路径允许部分错误新账本覆盖上次有效分析。也没有外部文件自动监测，仅提供显式 Reload（`:215`）。

4. **P1：查询丢失类型与 NULL。** R02 要求“查询整数和类型保持无损；缺价/NULL/真实零有不同呈现”。`N/internal/ledgerapp/document.go:235` 只保存列名，`:245` 将每格转成字符串。`N/vendor/beancountgo/query/types.go:146` 与 `:148` 使 NULL 和空字符串都成为空文本。原生结果及其 CSV 无法保留当前类型契约。

5. **P1：查询取消、预算和成功结果保留缺失。** R07 要求“成功结果和错误分离……取消与预算有效”。`N/internal/ledgerapp/document.go:229` 先无 context 全量执行，`:233` 至 `:241` 在执行完后截取一万行。这不是执行预算。查询期间全局 busy；没有 Cancel Query。`N/app.go:292` 至 `:295` 在错误时清空上次成功结果。

另有范围增加：当前设计要求“后续原生写账应另按 reviewed write workflow 设计”。外部预览已经提供原文件编辑与保存（`N/app.go:232`、`N/internal/ledgerapp/files.go:138`）。这需要独立功能范围，不能随阅读客户端替换一起接入。

可借鉴的实现思路包括实际读取 callback、文件身份与内容复核、输入上限和迟到结果清理。冲突保存属于后续写账范围。

Spec：5 项替换阻断，另有 1 项范围增加；直接影响分析可信度的问题是错误重载替换有效分析。

外部 v16 剩余失败已收敛到两类。

- `.ico` 响应在本机为 `image/x-icon`，Linux 原版冻结期待为 `image/vnd.microsoft.icon`。`C/fava/http_response.go:307` 调用环境相关的 `mime.TypeByExtension`。受影响包 `beancountgo/fava`，包括文件响应与 URL projection 测试。没有证据表明这一差异改动了账务金额，但严格 HTTP 等价门槛没有通过。
- 目录夹具同时创建 `docs/assets` 和 `docs/Assets`。本机文件系统合并大小写名称，`invalid-components` 的 Linux 期待无法保持。受影响包 `beancountgo/doctor`、`beancountgo/cmd/bean-doctor`。这暴露了测试夹具的平台假设，不能直接解释为目录验证算法必然错误。

本轮不重复相加测试数量，也不将交付方的旧状态标签视为当前验收。详细计数、跳过原因和失败输出见 [test-summary.json](review-evidence-2026-10-12/test-summary.json) 与 [macos-failure-details.txt](review-evidence-2026-10-12/macos-failure-details.txt)。原始 JSONL 已压缩保存。

## 4. 合并处理建议

| 项目 | 当前处理 | 后续完成条件 |
| --- | --- | --- |
| 外部整套核心和 Native UI | 暂不合并，不替换当前工作树 | 先明确是否改变独立实现、来源声明、插件契约和桌面技术约束；若保持当前契约，应拆解为专项移植。 |
| BQL `DISTINCT` / `HAVING` / 子查询 / `PIVOT BY` | 优先作为当前兼容缺口的验收用例与行为参考 | 在当前 `internal/query` 实现，保留类型/NULL、执行预算、取消及现有接口；用固定 BeanQuery oracle 验证，覆盖 CLI 与 `desktop.Session`。 |
| 插件缓存和金融插件修复 | 保留外部产品的验证结论 | 当前不执行插件，无对应移植目标。不得顺带引入插件注册/执行来套用该修复。 |
| CSV 周日期 | 先映射到当前实际需要的导入接口 | 确定目标接口和严格日期差异，完成原生实现与失败无部分提交的回归；不能直接套用外部补丁。 |
| MyGO `v0.3.6` | 作为独立依赖升级候选 | 逐项处理当前 fork 的选区、组合输入、系统面板与生命周期接口，补新证据。 |

优先保留并完善当前已实现的 `apps/goui`。本轮没有证据支持用外部预览接管它，也没有证据支持直接合并后宣称完整 Beancount/Fava 等价。

Standards 共 4 项，最严重为来源声明冲突；Spec 共 5 项替换阻断，直接影响分析可信度的是错误重载替换有效分析。
