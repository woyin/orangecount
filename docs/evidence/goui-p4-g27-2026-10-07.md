# G27 类型化查询结果首轮证据

日期：2026-10-07。本记录说明 G27 当前代码与自动化覆盖，不表示整个 G27、P4 或 Go UI 迁移完成。

## 实现

- 查询结果 Table 有固定的 320 DIP 高度和内置滚动区域，行按快照/profile/执行请求指纹、离线文件身份与行号保持稳定身份。结果上下文变化会清除选择；typed column schema 变化会清空旧排序，并只恢复相同 schema 摘要对应的列顺序和宽度。
- 选中行展示每个有序 typed cell。decimal 使用精确值；amount、position、inventory 显示单位、成本金额、日期和标签；dictionary/list/transaction 等递归 metadata 保留子类型并最多渲染 199 项，避免单行大型 metadata 撑开 UI。
- “复制类型化结果行”复制 QueryContext、typed contract、原序 columns 和原始 cells。数值沿用核心字符串表示，不把整数转换成浮点数，也不丢掉 position 全成本。
- 可排序列复用 `query.CompareCells` 的核心 typed 排序：精确整数/decimal、字符串/日期、bool、amount、position、inventory；NULL 顺序和复合比较与查询 `ORDER BY` 一致。核心不支持排序的 list/metadata 列不显示可排序表头。
- 排序使用显示行索引映射，不改写捕获结果；排序切换后继续选中原结果行，行复制仍按原行身份取值。

## 验证

- `TestQueryPageExecutesExplicitDraftAndRendersTypedResults` 用真实查询检查重复标题、NULL 与空字符串的不同显示。
- `TestQueryPageSelectionCopiesTypedContextAndFullPositionCost` 用 `compound-values.bean` 检查可选行详情、复制后的请求上下文、列顺序、类型和批次成本日期/标签/精确值。
- `TestQueryCellDetailsPreserveNestedTypesExactIntegersAndBoundExpansion` 检查递归元数据中的 NULL、空串、近似 decimal 与超大整数精确文本，并验证大型字典最多展开199项。
- `TestQueryPageKeepsTenThousandResultRowsVirtualized` 将10,000行 typed rows交给结果表，确认首帧只生成有限可见数值单元格。
- 同一10,000行测试继续覆盖鼠标滚动到末端、首行鼠标选择、Home/End 键盘选择及末端详情；`TestQueryTableSortsTypedIntegersAndKeepsSelectedRowForCopy` 覆盖表头升/降序、数字而非字符串排序、选中行身份与复制。
- `TestQueryPageRendersZeroRowTypedResultSchema` 从真实 DesktopEngine fixture 执行零行查询，并检查表头/schema、0 行状态、无错误选中以及空表排序行为。
- 核心 `TestCompareCellsUsesExactCoreOrdering` 覆盖 NULL、超大整数、1/3 精确 decimal、金额、position、inventory 和 bool；不支持的集合排序会返回错误。
- `TestOfflineQueryAnalysisLoadsTypedResultWithoutTouchingActiveLedger` 与核心 archive reader 测试检查离线捕获展示和旧 scalar contracts 的读取路径。
- 以下检查通过：`make goui-check`；`GOWORK=off go test -race -count=1 ./...`；`GOWORK=off CGO_ENABLED=0 go vet ./...`；`make license`；`git diff --check`。
- 在G27排序/零行场景和同轮workspace导出协调加入后，当前源码复跑：`make goui-check`、Go UI全模块 race 测试、Go UI `go vet`、根模块全量测试、`make license`、`git diff --check` 均通过。
