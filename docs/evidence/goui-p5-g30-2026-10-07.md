# G30 固定捕获协调验证

日期：2026-10-07。记录查询和报表两种导出身份如何收敛到每窗口唯一保存槽和共用原子文件保存路径。

## 实现

- Workspace 新增 query capture intent/state。开始前要求活动窗口有成功 query response，并核对当前 snapshot、request ID、fingerprint 与 CSV/analysis 格式；`desktop.Session.CaptureQueryExport` 在核心再次核对缓存成功结果。
- 捕获结果复制 content、QueryContext 和 protected paths 到窗口状态。捕获成功后 reload、另一个查询或失败查询不会改写已冻结字节；workspace 状态防御性复制也隔离调用者修改。
- 同窗口的 report/query 捕获不会同时执行。报告捕获 dispatch 还会核对当前 workspace response 的 `ReportExportIdentity`，拒绝已过期 projection；查询 capture 核对 request ID/fingerprint。
- 核心 query 导出没有中止 serializer 的取消 API。用户取消后 workspace 保持 cancelling/busy，等有界 serializer 返回后丢弃结果；账本切换/关窗会立即使旧 capture epoch 失效，迟到字节不发布。
- 查询和报表共用单一 `activeExportID`、取消入口、Save Panel 后的 `ExportProtection` refresh 以及 `saveCapturedExport`；capture identity 按业务类型分别校验，固定内容不依赖草稿或面板期间的新读取。

## 验证

- `TestDesktopEngineQueryPublishesTypedSuccessAndFailure` 用真实 DesktopEngine 打开公开 `default-source.bean`、执行两个同名列查询并捕获 CSV；内容为 `v,v\n1,2\n`。之后执行失败查询，已捕获字节仍保持不变。
- `TestQueryCaptureFreezesSuccessfulBytesAcrossReloadAndLaterQuery` 覆盖缺少成功结果、stale identity、未知格式拒绝，query/report 不能并发捕获，reload/后续 query 不替换 bytes，返回状态的调用方 mutation 不影响 workspace capture。
- `TestQueryCaptureCancellationDropsLateResult` 覆盖取消中的 busy 状态、迟到结果丢弃和窗口关闭期间的晚到完成丢弃。
- `TestReportCaptureRejectsProjectionOutsideCurrentView` 覆盖不匹配当前报表 identity 的旧 projection 拒绝；报表 capture/reload 的保存集成测试验证冻结内容与保护路径更新。
- G32/G33 app integration tests 验证报表与查询两路实际文件保存、取消不落盘、reload 后新 source 仍受保护；MyGo 可取消原生 Save Panel 的成功/取消/预先取消路径通过。
- 上述 capture/race 用例执行 `GOWORK=off go test -race ./internal/workspace -run 'TestQueryCaptureFreezesSuccessfulBytesAcrossReloadAndLaterQuery|TestQueryCaptureCancellationDropsLateResult|TestDesktopEngineQueryPublishesTypedSuccessAndFailure' -count=10` 通过。
- 当前源码全量门槛也通过：`make goui-check`、Go UI `go test -race -count=1 ./...`、Go UI `CGO_ENABLED=0 go vet ./...`、根模块 `go test -count=1 ./...`、`make license` 和 `git diff --check`。
