**交付目标与范围**

首个交付版本应能让用户每天打开本地账本，可靠地阅读资产负债表、损益表、交易流水和趋势；外部编辑期间保持一致的数据，错误可定位，修复后可恢复；生成可验证的 macOS 安装产物。

保持现有 SwiftUI + Go C-Archive、单进程、离线、无本地 HTTP 服务的架构。会计规则继续由 Go 核心承担；Swift 负责界面、交互和显示。账本 `.bean` 文件及 include 图仍是权威数据源。

本阶段只读：不加入原生编辑、快捷记账、导入、规划、持仓专页或查询工作台，也不开展整个 Web 前端迁移。发现共享核心的问题时，以有针对性的修复和回归验证处理，不顺带重构解析器、求值器或整个 Web 层。

当前“日记账流水”的交付范围为交易及其分录。开户、余额断言、价格等全部指令的 Fava Journal 展示属于后续功能，不以“完整 Journal 等价”描述本阶段。

**P1：先把现在的四个页面的数据修正**

1. 统一 JSON 集合规则：列表无数据时返回 `[]`，映射返回 `{}`；可选值、无有效快照、请求失败分别表达。Swift 不通过大量 `try?` 把协议错误吞成空页面。升级协议增加明确版本号，旧新客户端不兼容时返回可诊断错误。
2. 修正收支适配：按明确序列名提取 Income 和 Expenses，排除 Net profit；展示收入按记账符号取反，支出保留净支出符号，结余用精确数相减。不能使用绝对值，否则会误报退款、冲销和收入转回。上述 1000/300 fixture 的展示结果必须为 1000/300/700。
3. 拆分重复 `operating_currency` 为独立币种列表。优先选择账本的首个本位币，允许切换；没有本位币时保持原币种显示并提示选择，不静默当作 USD。缺汇率或数据不可折算时，保留可用性状态，不把未能计算的结果显示为可信的零。
4. 账户树与流水金额保留精确值，并采用一致的可读显示。图表坐标可以用浮点数，金额标签、提示和导出来源仍保留精确值。汇总、转换和符号变换都在 Go 完成。
5. 补全交易分录的成本、价格和来源位置。导出结构化字段，明确单价/总价、成本币种等含义；Swift 只渲染。复用已求值交易，包括自动平衡后的分录，不重新推断账务。
6. 修正统计命名：`entries_count` 包括非交易指令，不能标为“交易笔数”；分别提供交易数和账户数，账户数明确是否含已关闭账户。
7. 区分错误种类：账本诊断、会话/请求错误、协议/解码错误不能共用一段字符串。移除普通解码错误中的整段原始 JSON，以及默认日志中的完整账本路径；本地来源查看仍可按用户操作显示必要信息。

主要落点：`internal/bridge/bridge.go`、`internal/report/presentation.go` 的现有能力、`Models.swift`、`BridgeClient.swift`、`DashboardView.swift`、`JournalView.swift`。只在共享语义确有缺口时修改 `internal/report`。

验收：现有合法 fixture 的所有读取接口均能被真实 Swift 客户端解码；空数据有正确空态；收支、退款和多币种有独立期望值；成本买卖信息不丢失；缺汇率不会展示误导性 KPI。Go 层测试与 Swift 链接测试均通过。

**P2：建立一个负责数据一致性的账本会话 Module**

建议新增 `internal/desktop`，管理会话、重载调度和只读投影；`internal/bridge` 只承担 C ABI 与序列化。复用 `snapshot.Store`、文件监听规则及现有 report/query 能力。Swift 不调用 Web HTTP，也不依赖 Fava HTML 投影；仅在确实被两个调用方使用时提取共用投影。

建议 Interface 收敛为以下操作，名称可按最终代码规范调整：

| 操作 | 职责 | 必须满足的约束 |
| --- | --- | --- |
| OpenLedger(path) | 创建会话并尝试首次构建，返回不透明句柄 | 无效账本仍能返回诊断会话；C ABI 不向 Swift 暴露 Go 对象地址 |
| PollState(handle, lastRevision) | 读取状态版本是否变化 | 只读内存；不读文件、不构建快照、不生成报表 |
| ReadView(handle, request) | 从一个已捕获快照生成当前页面和摘要 | 响应携带快照 ID、状态版本、请求参数；内部不能重新 Build |
| Reload(handle) | 发起一次手动重新校验 | 与监听触发共用串行构建路径，合并重复待处理请求 |
| CloseLedger(handle) | 关闭会话、停止监听并释放引用 | 关闭与进行中读取并发安全；关闭后调用返回明确错误 |

Implementation 要点：

- 每个窗口先持有独立会话；不同账本完全隔离，同一账本多窗口只读也保持正确。先不增加跨窗口全局缓存。将来加入写入时，再建立按规范化路径共享的写入协调，避免多个 Writer 并行修改同一账本。
- 打开一次账本只做一次完整构建；后续报表共享该快照。`Evaluation()` 的防御性复制也要纳入测量，避免只是消除了 Build、却继续给每个页面重复复制和投影整个账本。
- 复用 `snapshot` 的 stat-only 探测规则，覆盖入口文件、最近一次尝试的 include 图和缺失 include 目标。需要提取小范围探测能力时，Web 和 desktop 使用相同实现及回归用例。
- 文件监听与手动刷新经会话的同一串行重载队列执行；若构建期间再次检测到变化，完成后最多追加一个待处理重载，避免并发构建和丢失最后一次修改。
- 状态版本与有效快照 ID 分开：错误消息改变也增加状态版本；有效快照 ID 只标识可供计算的账本内容。禁止用统一的 `rev:invalid` 代表所有错误状态。
- 首次打开非法账本：显示诊断，没有报表；已有有效快照后编辑出错：保留该账本上次有效报表，并明确标注“显示上次有效数据”和最新错误。切换到另一本非法账本时，不能把前一本数据挂在新路径下面。
- 一次响应捕获同一组快照、诊断与状态元数据，避免分别加锁读取造成混搭。过滤、币种或估值改变只重新投影，不触发磁盘重建。
- 从当前页面按需生成数据，后台可预取下一页；缓存仅在基线表明有必要时加入，并以快照 ID 与完整请求参数作为键。

验收：稳定文件变更只产生一次构建；空闲 60 秒无内容读取和快照重建；所有报表请求使用指定有效快照；连续两种错误能分别刷新；删除和恢复 include 可自动恢复；新错误不覆盖最后有效快照。新增会话并发测试及 `go test -race` 通过。

**P3：把 Swift 状态流变成可验证的行为**

1. 从 `main.swift` 提取 `LedgerStore.swift`，主入口保留组装与 Scene；Store 由 `@MainActor` 管理。C ABI、磁盘相关操作和大 JSON 解码放到受控后台执行位置。
2. 按实际 C 客户端和可控测试客户端建立一个小 Interface，用于验证延迟、乱序和失败。避免为所有 View 增加抽象层。
3. 定义明确的界面状态：未打开、正在打开、可用、后台重载、保留旧快照但有错误、首次打开失败、会话错误。`loading` 不与空结果混用。
4. 所有请求携带窗口会话、请求代次和过滤参数标识；新请求取消旧任务，并在结果提交前验证代次。同步 C 调用可能已经开始执行，因此不能只依赖 Swift Task 取消。
5. 导航与报表类型保留一个权威状态，删除 `selectedNav` 和 `reportType` 的双向漂移。消除首次加载时重复触发的账户树请求；切换到新账本后按明确定义的当前路由加载。
6. 同一本账本重载保留搜索、折叠、选择；切换账本隔离这些状态。交易 ID 明确区分快照内标识与跨重载恢复策略，不能用全局数组下标承诺稳定性。只在条目能够明确匹配时恢复展开，避免把状态套到另一笔重复交易上。
7. 窗口关闭、换账本、打开失败、快速取消时，都释放会话和轮询任务。Store 不持有永不结束的定时器或后台任务。

验收：可控测试令 A 请求晚于 B 返回，界面仍保持 B 的路径、数据和诊断；快速切换报表不会错配标题和内容；关闭窗口不再触发调用；重复开关 20 次会话数回到基线；两个窗口的数据与状态隔离。

**P4：把已有页面做成可日常使用的阅读工具**

1. 账户树：账户名过滤保留祖先路径、必要时临时展开匹配路径，清空搜索恢复用户折叠；提供全部展开/折叠。搜索只过滤显示，父节点汇总仍代表整个子树，界面需说清口径。
2. 报表：资产负债表采用截至某日余额；损益表采用明确期间发生额。沿用现有 Go 报表和区间能力。日期范围、币种、原币/成本口径均可见；改变过滤后表格、KPI 和图表使用相同口径，区别只允许是明确标注的图表显示窗口。
3. 流水：提供日期范围、排序、账户过滤和普通文本检索；准确显示收款人、摘要、标签、链接、分录、成本和价格。第一版不把普通文本搜索描述为完整 FQL。默认近期窗口和图表 1Y 窗口按现有已记录偏好实现，并提供 All，日期锚定账本最新日期而非今天。
4. 长流水：先按固定合成账本测量，若全量传输/搜索超预算，再加会话内过滤和分页，所有页面绑定同一快照。不能直接混用不同快照的页。列表虚拟化不等于传输和过滤已经足够快。
5. 诊断：传递 code、severity、文件标识、行列和相关位置，复用 `repairguidance`。明确区分错误与警告，提供复制位置、Finder 定位、打开源文件与重试。编辑器不支持跳行时只承诺打开文件和显示行号。
6. 图表：加入精确金额提示、明确币种与估值口径；数据不足、无记录、不可折算分别显示。区分收入/支出与结余，不把净利润折线当成额外支出。
7. macOS 交互：`Cmd+O/R/F`、键盘导航、菜单与焦点一致；支持 Finder 打开文件、目录入口解析和拖入；最近打开去重且不让失效路径阻断首次启动。将欢迎空态设为正常行为，生产启动不隐式读取仓库 fixture。
8. 对本阶段界面补齐中英文字符串和数字显示，切换语言不改变账务。检查最小窗口尺寸、长账户名、多币种、Light/Dark、大字体与辅助功能标签。

主要落点：现有 Swift 视图、`LedgerStore.swift`、native DTO 和只读投影、诊断知识库的现有公共能力。保持已批准的原生材质和 Charts 风格；本阶段不另起一轮视觉改版。

性能建议预算（P0 后锁定测量条件；以下为目标，不是已测结果）：

- 固定约 52,500 笔交易账本，首次页面可操作目标不超过 2 秒；冷/热加载分开统计，不能只选最好一次。
- 首次加载后，常用过滤和页面切换 p95 目标不超过 200 ms；大账本如需分页，记录首屏耗时和总记录数。
- 已完成防抖的变更，在一次构建耗时之外，状态发布额外延迟目标不超过 300 ms；单独报告文件检测和防抖时间，不承诺任意账本 0.8 秒以内更新。
- 主线程无 Go Build、文件扫描或大 JSON 解码；空闲构建计数为零。针对输入、滚动与切换记录卡顿，移除没有设备和测量证据的“120 FPS”承诺。

预算未达标时先定位耗时并修复；若需要调整预算，记录测量依据和用户体验影响，不静默提高门槛。

**P5：让产物和完成度声明可核实**

1. 保留 `make app` 开发入口，显式设置且校验 Swift、cgo/C 链接和 `Info.plist` 的 deployment target；锁定可复现的工具链选择方式。用 Mach-O 元数据检查代替只检查 plist。
2. 首个交付优先 Apple Silicon；Intel/universal 保留为后续支持项，只有编译和运行都验证后才写入支持矩阵。macOS 13 是待验证支持目标；如果工具链或现有 API 不支持，明确列出适配成本，再决定调整目标，不能只改 plist 宣称支持。
3. 将开发构建、测试构建、分发构建区分：测试使用固定脱敏 fixture 和隔离偏好设置；正常 app 无开发回退路径。版本号、bundle 标识、资源、退出行为与许可文件完整。
4. 增加 macOS CI，跑 Go 核心检查、真实 C ABI/Swift 测试、Swift 状态测试、app 构建和最低版本元数据检查。现有 Linux CLI 发布流水线保持独立，不能将 CGO_ENABLED=0 的 CLI 流程当成原生 app 发布验证。
5. 用固定 fixture 做窗口启动与操作验证，断言实际加载状态及关键数据显示；进程存活一秒只能叫启动存活检查。GUI 测试在可用的 macOS 测试环境完成；环境缺失的场景如实标注，不能自动算通过。
6. 产出 app 压缩包、校验和和支持矩阵。对外分发时再执行 Developer ID 签名、公证和目标机器验证；证书/机器缺失只影响对应分发验收，其余可完成工作继续推进，不将本机启动等同于用户可安装。
7. 更新 `README.md`、`docs/development.md` 和原生验收报告：写清已实现范围、测试输入、运行环境、已知限制。删除“100% Fava 等价”等超出证据的表述，用具体行为清单替代。

验收：干净 checkout 能按文档构建；目标机器可打开 app、选账本、查看、触发错误并恢复、关闭；最低版本声明与实际验证一致；测试不会自动读取私人账本；版本、许可和校验和可核对。

**最低验收矩阵**

| 场景 | 必须观察到的行为 | 主要验证层 |
| --- | --- | --- |
| 有账户、无交易 | 合法空流水；不出现 JSON 解码错误 | Go + 真实 Swift/C ABI |
| 无 Income/Expenses | 合法空损益表；可切回资产负债表 | Swift/C ABI + GUI |
| 收入 1000、支出 300 | 展示收入 1000、支出 300、结余 700 | 独立固定期望值 + GUI |
| 退款与冲销 | 保留经济方向，不能被 abs 变为正支出 | Go 投影 + Swift/C ABI |
| USD/EUR、多币种无汇率 | 独立币种；不可折算状态明确；不显示伪零 | Go + Swift/C ABI + GUI |
| 成本买卖、总价与单价 | 已求值金额、成本和价格完整且含义正确 | 核心 fixture + Swift/C ABI |
| 有效 → 错误 A → 错误 B → 修复 | 同账本保留有效视图；两次诊断都更新；修复后发布 | 会话 + GUI |
| 首次打开非法账本 | 诊断可见，不借用其他账本的报表 | Swift 状态 + GUI |
| include 删除、补齐、调整 | 最新尝试图和缺失目标均被监听 | Go 会话集成 |
| A 慢响应、B 快响应 | 当前路径、报表、诊断始终属于 B | 可控 Swift 状态测试 |
| 日期/币种/页面快速切换 | 不出现参数与数据错配；不重建账本 | 会话计数 + Swift 状态 |
| 外部保存连续多次 | 构建串行且防抖，最终显示最后有效版本 | 文件集成 + race |
| 空闲 60 秒 | 零内容读取、零 Build；只做属性探测和轻量状态读取 | 计数/性能探针 |
| 开关窗口 20 次、两个账本窗口 | 无残留会话/监听，窗口之间不串账 | 生命周期 + GUI |
| 目标系统上的安装产物 | 启动、查看、重载、错误恢复和退出通过 | 目标机器实际验收 |

会计预期优先来自现有脱敏 golden 和可人工核算的小账本。单纯拿同一个 Go 函数的两个包装互相比较，只能证明适配一致，不能证明会计语义与外部参考等价。扩展会计语义时再运行相关 Beancount 差分测试。

**提交拆分与检查策略**

实施时建议采用以下小批次；每一批都保持可构建和可审阅。本次仅制定计划，不创建提交。

| 批次 | 交付内容 | 主要文件责任范围 |
| --- | --- | --- |
| C1 | 跨语言测试入口与空集合修复 | native tests、bridge、Models、Makefile |
| C2 | 收支、币种、金额显示与缺汇率状态 | desktop 投影前身、report 必要改动、Dashboard |
| C3 | 流水成本/价格、来源、统计、结构化诊断 | bridge DTO、Journal、Diagnostics |
| C4 | Go 会话与单快照读取 | 新 desktop Module、bridge、snapshot 必要小改动 |
| C5 | 串行重载、stat-only 监听、失效与恢复 | desktop、snapshot、会话测试 |
| C6 | MainActor Store、请求代次和资源生命周期 | LedgerStore、BridgeClient、ContentView、Swift tests |
| C7 | 过滤、期间口径、展开恢复、诊断来源 | Go 只读投影、现有 Swift Views |
| C8 | 原生文件交互、快捷键、语言和显示 | App/Scene、资源、本阶段视图 |
| C9 | deployment target、CI、构建产物与证据报告 | build.sh、Makefile、workflows、docs |

C1–C3 对现有路径做有界修复；C4–C6 完成同一会话迁移，不长期保留两套默认数据路径。遇到 C2/C3 与后续会话接口重叠时复用 DTO 和投影，不复制实现。

每个批次先跑影响范围内的测试。会话与共享核心改变后运行相关 race 测试；阶段集成时运行 `make fmt vet test race license build` 以及 mac 专用门槛。拟新增 `make mac-test`（Go→C→Swift 与 Swift 状态测试）和 `make mac-check`（集成门槛），名称在落地时固化。现有 `verify-native-equivalence` 应迁移为真实可执行检查，旧命令可保留兼容入口但不得继续伪报验收结果。

只有改变 Web 共享契约或前端时才增加对应 Web 检查；没有前端改动不重跑整套视觉采样。文档改动检查链接和计划一致性，不为文档另建实现镜像测试。

**首个版本的完成定义**

P0–P5 的行为验收全部有对应证据；已知金额、币种、空数据、乱序和热重载问题已修复；无未解释的重大数据一致性问题。用户能在声明支持的环境完成“打开 → 查看 → 外部修改 → 出错定位 → 修复恢复 → 退出”。

工作量估算、编译通过、Go 测试通过、GUI 场景通过、目标机器安装通过是不同状态，交付报告分别列出。缺少旧系统/Intel/分发证书时限定支持声明，不把未验证项勾为完成。
