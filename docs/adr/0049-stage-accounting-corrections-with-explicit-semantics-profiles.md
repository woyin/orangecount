# 用显式语义配置分阶段交付会计修正

本轮发现隐含成本日期、LIFO、全局 booking、STRICT 和容差的实际语义差异。直接修正可能改变已有账本的有效性、库存与盈亏；只保留现状又无法达到 ADR-0005 的 v3 兼容目标。依照 ADR-0013，决定先保留用于比较旧结果的 `legacy` 配置，通过显式 `v3` 配置交付修正，并在快照、会话和结果中记录配置。切换要先比较相同输入，再新建会话；不能复用另一配置的快照或悄悄改默认。

`v3` 配置采用账户声明 → 全局 booking → 上游默认 STRICT 的优先级。AVERAGE 作为单独登记的扩展，仅在账户或全局声明中被明确选择时执行。本决策修订 ADR-0042 中关于默认 FIFO 及仅每账户启用的限制，保持其懒合并、最早日期和拒绝跨成本币种等数学契约。

2026-10-01 用户明确授权按三份设计/计划/实施文件完成开发，因此接受显式配置、迁移比较及 AVERAGE 的启用契约。默认配置切换和 legacy 撤除仍以实际迁移证据及后续明确决策为准，未在本次实施中接受。具体行为、能力边界与验收见 [设计](../go-beancount-native-design-2026-09-30.md)第 5–8 节。

曾考虑直接修改全部默认行为，因会静默改变已有会计结果而未采用；也未采用永久保留两套独立引擎，以免新能力和修复长期分叉。legacy 的用途限定为兼容保护和迁移比较，新增分析能力以 v3 验收。
